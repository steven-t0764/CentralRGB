# Changelog

Changes that users will notice, newest first. Agents add a line under **Unreleased** with every change.

## Unreleased
- **Smoother preset effects:** the preset colourways (Drizzle, Stardust, Eclipse, Cyberpunk and the rest) no longer step or pop. Each LED now shows the effect blended across its width and over the moment between updates, so edges glide from LED to LED and RAM (which can only update a few times a second) fades between updates instead of jumping. Cyberpunk crossfades its blocks, Pulse flickers less harshly, and the in-app previews run at about 60 fps. <!-- feature -->
- **Logitech G915 X explained:** OpenRGB can't light the G915 X (wired or LIGHTSPEED) yet, so when one is plugged in the Devices page now says so, links the OpenRGB request, and suggests keeping its lighting in G HUB until support arrives.
- **Case fans and strips on motherboard headers light up:** OpenRGB can't count the LEDs plugged into an ARGB header (JRAINBOW on MSI boards), so it starts them at 0 and fans on them stay dark. Open the board on **Devices**, press **Customize** and set **Connected LEDs** for each header; Central RGB remembers it and sets it again every time it starts. The Devices page says which headers are still at 0 (type 0 for one you don't use to hide the note). <!-- feature -->
- **Keyboards and mice found late still show up:** when OpenRGB takes minutes to finish looking for hardware (for example while SteelSeries GG holds a SteelSeries mouse), Central RGB no longer stops listening after about 30 seconds: it keeps going for as long as OpenRGB says it's still detecting (up to 10 minutes), adds devices as they appear, and says what OpenRGB is waiting on and which app to close.
- **Fan list in the activity log:** the fans the hardware monitor finds (name, chip, RPM) are written to the activity log, to help when a fan doesn't show up on the Fans page.
- **Smoother and lighter everywhere:** Central RGB lags and stutters less and uses much less CPU, especially when your lighting is a still colour, the app is idle, or it sits in the tray. The Lighting, Home and Devices previews, the lighting engine, the sensor monitor, settings saving and the activity panel were all made cheaper. <!-- big -->
- **Settings saved a moment after a change:** dragging a slider no longer rewrites `settings.json` over and over; changes are written about half a second after you stop, and always when you close the app. The file looks the same and older settings still load.
- **Activity panel keeps recent lines:** **Settings → Activity** now shows only the latest 500 lines so it never slows down in a long session. The full log is still in `%APPDATA%\CentralRGB\activity.log`.
- **Less background work:** slow Monitor extras (process count, CPU clock, disk usage) refresh less often, the overlay only checks the game or redraws its preview when it is on or showing, and the lighting previews skip frames that wouldn't change anything.
- **RAM message no longer blames an "OpenRGB 0.0.0":** OpenRGB leaves its Windows version number blank, and Central RGB read that as version 0.0.0 and said it was too old for RGB RAM. A blank version now counts as unknown; an OpenRGB with PawnIO modules next to it is recognised as 1.0 or newer; and if Central RGB is using an OpenRGB it didn't install and can't tell its version, the Devices page names that folder and says how to switch to OpenRGB 1.1.
- **Updates arrive on their own:** new versions are now published automatically once a batch of changes (or one big change) is finished and tested, so **Settings → Updates** always finds the newest version without waiting for a manual release.
- **Sidebar and page change together:** the sidebar no longer lights up the new page while the old page is still showing (for over 100 ms the first time a page opens, a few frames after that). The highlight now moves in the same repaint as the page.
- **Old agent setup removed:** the leftover Vizor 0.14 config, plan, status report and skills were removed from the repository; the app itself is unchanged.

## 2.4.0 (2026-11-20)
- **Corsair Vengeance RGB PRO RAM:** sticks Windows lists with the maker "Unknown" (for example 4x CMW32GX4M2D3600C18) now show as **Corsair Vengeance RGB PRO** in the Settings system check; the maker and product line are read from Corsair part numbers (CMW, CMN, CMG, CMR, CMH, CMT, CMP, CMK...) and from JEDEC maker codes. When Central RGB downloads OpenRGB it now always picks the newest Windows build that is 1.0 or newer (older ones can't reach RGB RAM on Windows 11), notes which version it installed, and the activity log says which OpenRGB version starts. If OpenRGB's RAM detectors were switched off in OpenRGB's settings and RGB RAM is installed, they are switched back on before OpenRGB starts. When RGB RAM still isn't found, a **RAM diagnostics** report (OpenRGB version, how it was started and whether it runs as administrator, PawnIO and its SMBus modules, the CPU's SMBus, OpenRGB's RAM detectors, the apps holding the SMBus, OpenRGB's own SMBus log lines and the RAM part numbers) is added to the activity log and saved to `%APPDATA%\CentralRGB\ram-diagnostics.txt` to copy into a bug report.
- **Page switching and scrolling fixed:** switching pages no longer leaves parts of the previous page on screen (for example the Overlay header over the Monitor graphs), scrolling Settings no longer smears rows into repeated copies or blank bands, and the sidebar highlight changes together with the page. The window is no longer kept very slightly see-through (that made scrolling smear and redraw slowly); restoring from the taskbar still shows the window only once it is drawn. If anything isn't drawn yet for a moment it shows the panel colour, never black or the old page.
- **Status report:** [docs/vizor-report.md](docs/vizor-report.md) lists in short what works now and what still doesn't (or hasn't been tried on a real PC), with a link to the PR or review for each item.
- **Light mode polish:** in Light, slider knobs no longer vanish while you hover or drag them (a deeper shade instead of white), the white colour swatches have a thin outline so they don't look like an empty gap, Breathing previews and LED strips fade into the card instead of dipping to a black bar, the selected row in Monitor → Advanced shows, graph guide lines are visible, and the speed slider in Create preset has a visible knob. Switching to Light also changes the title bar and window background before the new page is drawn, so there is no dark flash. Dark looks exactly as before.
- **Light mode:** **Settings → Appearance** now has **Dark** and **Light**. Light gives every theme bright Windows 11-style panels with dark, easy-to-read text and the theme's accent colour in a deeper shade, plus a light title bar on Windows. It switches instantly with no restart, and your lighting, fans and sensors keep running. Dark stays exactly as before and is still the default.
- **No more black flashes:** restoring the window from the taskbar no longer paints it black first, and switching sections no longer shows every label, card and sidebar item as a black box for a moment. The window keeps showing its last picture (or the panel colour) until the new content is drawn.
- **DDR5 RGB RAM:** DDR5 RGB kits (Kingston FURY, Corsair Vengeance / Dominator DDR5, G.Skill Trident Z5, T-Force Delta, XPG Lancer) are now recognised, and once OpenRGB finds them they get every effect at the steady RAM rate, like DDR4. With DDR5, OpenRGB searches for the RAM only once per boot: it keeps running after you close Central RGB, **Rescan** asks before searching again and **Close them** doesn't restart it. When the RAM isn't found, the Devices page says why: blocked (admin, PawnIO, another RGB app), already searched this boot (shut down fully), an OpenRGB too old for DDR5, or a kit OpenRGB doesn't support yet.
- **RAM and mouse not detected:** the Devices page now also notices a missing RGB mouse, and names the program holding it (for example SteelSeries GG) or the RAM (MSI Center / Mystic Light), plus what to change: an old OpenRGB that Windows 11 blocks, or an OpenRGB you started yourself. **Close them** now also stops every MSI Center service and helper (including LEDKeeper2), says what it couldn't close, waits until they are really gone and then re-detects your devices exactly once. A hidden OpenRGB left from an earlier session is restarted by **Rescan** so it looks for the hardware again.
- **Updates:** if the connection drops while the update's checksum list is being read, the update notice now says so and offers **Try again** instead of staying stuck on "Downloading...".
- **Builds after auto-merge:** every pull request that merges itself now also starts the Windows build on main, so each merge commit gets its `windows` check (merges made by the workflow didn't trigger one before).
- **One-click updates:** Central RGB now checks for a new version (at most once a day, or with **Settings → Updates → Check now**) and shows a small notice with **Update now** / **Later**. Updating downloads the new installer (or the portable exe), checks it against the release's published SHA-256, closes the app normally so fans go back to the BIOS, installs it and reopens on the new version. Releases now include a `SHA256SUMS.txt`.
- **RAM not detected:** when other RGB software (MSI Center / Mystic Light, SteelSeries GG, iCUE) holds the RAM's bus, the Devices page now says which program it is and what to do, and RAM detection is retried once after "Close them".
- **RAM flicker:** RGB RAM now updates at a steady, lower rate, one stick at a time on the shared bus, skips frames that wouldn't change anything, and uses the sticks' own hardware modes for Breathing and Color Cycle where they have them.
- **FPS counter:** PresentMon restarts itself if it stops, the counter no longer locks onto launchers, overlays or anti-cheat helpers, and when it can't count it says why (for example "PresentMon needs admin") instead of disappearing.
- **Window restore and page switching:** restoring from the taskbar draws the window while it's hidden so it no longer flashes black, and fast clicks between pages no longer leave a half-built page.
